# NekoBox core как служба Windows (запуск до входа в систему)

Статус: код написан и проверен статически (gofmt, go vet и кросс-компиляция
service_windows.go под windows/amd64 на заглушках для gen/internal). Полная сборка
NekoBox, запуск службы и холодный старт НЕ выполнялись: их нужно проверить на вашем ПК.
Основа: исходники qr243vbi/nekobox, ветка main, коммит 5f6ebb0 (04.11.2026).

## 1. Как устроено

    Windows (до входа)            После входа robbo
    ------------------            -----------------
    SCM -> NekoBoxCore (SYSTEM)   nekobox.exe (GUI, как сейчас по задаче)
            |                         |  читает ProgramData\NekoBoxService-ipc\status.json
            | nekobox_core service run|  подключается к core.sock (не запускает свой core)
            v                         v
      RPC (Thrift) на Unix-сокете  <----  тот же интерфейс Start/Stop/..., что и раньше
      ProgramData\NekoBoxService-ipc\core.sock
            |
      sing-box (TUN, DNS, маршруты) + extra core (xray), если профиль его использует

* Конфиг не пересобирается в службе. GUI по-прежнему строит sing-box JSON своим C++ ConfigBuilder
  и шлёт его RPC-вызовом Start. Служба сохраняет последний успешный запрос
  (DPAPI, область "компьютер", каталог только для SYSTEM и Administrators) и флаг "enabled".
* При загрузке служба поднимает RPC, затем supervisor сам вызывает запуск из снимка.
  Если запуск не удался, повтор с нарастающей паузой (3 с ... 60 с).
* Кнопка "Отключить" в GUI = RPC Stop: служба останавливает ядро и снимает флаг "enabled"
  (после перезагрузки VPN не поднимется, пока вы снова не подключитесь).
  Остановка самой службы (выключение ПК, sc stop) флаг НЕ снимает.
* Закрытие GUI или выход из учётной записи ядро не останавливает: при выходе GUI в режиме
  присоединения вызов Stop пропускается (mainwindow_rpc.cpp, profile_stop_stage2).
* Если GUI просит Start с тем же конфигом, что уже работает, служба ничего не перезапускает.
  Если с другим, она останавливает старый профиль и запускает новый.
* Дубликатов нет: GUI не запускает CoreProcess, если служба жива; сам core в службе один.
* Сторожевой таймер (10 с): ядро упало или интерфейс TUN исчез на 3 проверки подряд -> перезапуск.
  После сна проверка выполняется через 8 с и перезапускает ядро при пропавшем TUN сразу.
  Падение самой службы: SCM перезапускает через 5 с, 5 с, 30 с.

## 2. Безопасность

* Раньше RPC слушал TCP 127.0.0.1 без аутентификации. Для SYSTEM-ядра это дало бы любому
  локальному пользователю запуск произвольного extra core и запись файлов. Поэтому служба
  слушает только Unix-сокет; каталог ProgramData\NekoBoxService-ipc имеет защищённый DACL:
  SYSTEM, Administrators и SID из service.json (allowed_users). Всем, кто в списке, фактически
  доверяется управление сетью компьютера.
* Дополнительно служба отклоняет: log.output в конфиге, extra core вне каталога установки
  (и extra_core_dirs), а рабочий каталог extra core подменяет на свой.
* Снимок профиля шифруется DPAPI (машинная область) и лежит под ACL; пароли и ключи не попадают
  в BAT/PS1/XML/service.json. Машинная область DPAPI защищает от кражи файла, но не от процесса
  с правами администратора на этом же ПК.
* Учётная запись: LocalSystem. Создание адаптера Wintun и изменение маршрутов требуют прав
  администратора; более узкие учётные записи (LocalService и т. п.) я не проверял и не использую.
* GUI от SYSTEM не запускается, Session 0 интерактивно не используется, UAC не затрагивается.

## 4. Сборка и установка

1. Применить патч (`git apply nekobox-service.patch`) к тому же коммиту или близкой версии main
   и собрать NekoBox обычным способом проекта (script/build_go.sh / CMake). Нужна версия,
   в которой есть mainwindow.cpp с блоком "Start core" (иначе патч C++ придётся перенести вручную).
2. Скопировать новые nekobox.exe и nekobox_core.exe поверх установленных в
   E:\applications\nekobox (предварительно закрыть NekoBox; сделать копию старых файлов).
3. Администратор PowerShell:

       Set-ExecutionPolicy -Scope Process Bypass
       .\Install-NekoBoxService.ps1 -InstallDir 'E:\applications\nekobox' -User robbo

4. Запустить NekoBox (как обычно), подключить профиль с TUN. В логе должно быть
   "[Service] Attached to the NekoBox core service". Служба запомнила профиль.
5. Перезагрузить ПК.

Задача планировщика "NekoBox AutoStart" не меняется: она запускает GUI, GUI присоединяется.

## 5. Обновление

Закрыть GUI, заменить файлы NekoBox, снова выполнить Install-NekoBoxService.ps1
(он остановит службу, обновит путь и запустит заново). Снимок профиля сохраняется.

## 6. Диагностика

    .\Get-NekoBoxServiceStatus.ps1        (от администратора)

* Лог: C:\ProgramData\NekoBoxService\logs\service.log
* Отладка в консоли: остановить службу, затем `nekobox_core.exe service run` (администратор).
* Нет присоединения GUI: проверьте, что ваша учётная запись в allowed_users
  (C:\ProgramData\NekoBoxService\service.json), heartbeat в status.json свежий (менее 30 с).
* Вернуть обычный режим для одного запуска: переменная окружения NEKOBOX_NO_SERVICE=1.
* Лишние nekobox_core.exe: скрипт диагностики предупредит, если их больше одного.

## 7. Откат

    .\Uninstall-NekoBoxService.ps1        # удаляет службу и данные
    .\Uninstall-NekoBoxService.ps1 -KeepData

Старые exe-файлы NekoBox возвращаются из копии; профили и настройки GUI службой не изменяются.

## 9. Известные ограничения

* Профиль появляется в службе только после первого подключения из GUI (снимка до этого нет).
* Если конфиг GUI содержит значения, меняющиеся при каждой сборке (например, случайные порты),
  при входе ядро один раз перезапустится вместо "тихого" присоединения.
* Пути правил (rule_sets) и кэша: служба использует C:\ProgramData\NekoBoxService\rule_sets
  и рабочий каталог work. Если ваши профили ссылаются на локальные файлы в каталоге GUI,
  укажите -RulesetDir/-ExtraCoreDirs при установке и проверьте.
* Fail-closed (запрет прямого трафика, пока TUN не поднялся) в службе не реализован:
  работает только strict_route из настроек TUN, пока ядро запущено. Правила брандмауэра для
  этого сделаны не были: без возможности тестирования это могло бы отрезать сеть.
* Unix-сокеты на Windows: в GUI опция core_use_uds по умолчанию выключена из-за "странных
  ошибок" (комментарий в DataStore.hpp). Этот вариант нужно проверить на вашей сборке Qt;
  если GUI не подключается, пришлите service.log и вывод Get-NekoBoxServiceStatus.ps1.
* Работа без сети на входе зависит от Windows: Wi-Fi до входа работает только для сетей,
  сохранённых для всех пользователей.
