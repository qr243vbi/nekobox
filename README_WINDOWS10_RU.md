# NekoBox: экспериментальное обновление для Windows 10 x64

Дата подготовки: 2 ноября 2026 года. Версия исходников: 5.11.28.7.
Это отдельная доработка исходного проекта, а не официальный релиз разработчика.
Установщик EXE и переносимая ZIP-версия собраны успешно. Проверены запуск интерфейса и ядра на Windows Server 2022 в GitHub Actions. На пользовательской Windows 10 работу с профилем и TUN необходимо проверить отдельно.

- [Успешная сборка Windows x64](https://github.com/dodon353/nekobox/actions/runs/41473340704).
- [Проверка запуска готового пакета](https://github.com/dodon353/nekobox/actions/runs/41473949203).
- Собранный коммит исходников: `2208449f021e42ec795b3a23d789a85ee3bd3f61`.

## Основа и проверенные версии

- NekoBox: `qr243vbi/nekobox`, коммит `eb3c5d7f6c28c7236584b996c57c3c8f03331938` от 1 ноября 2026 года.
- 3x-ui: `v3.11.0`, изучены генерация и импорт клиентских ссылок.
- Xray-core: `v26.10.31`, изучен исходный код обработки TLS/REALITY; официальный Linux-бинарник проверен по SHA-256.
- Зависимости sing-box сохранены из исходного проекта: расширенная реализация через `replace` в `core/server/go.mod`.

Версии проверены на указанную дату. При более поздней сборке это фиксированные версии, они не обновляются автоматически.

## Изменения

1. Упаковка Windows и Linux получает Xray 26.10.31. Перед распаковкой архив сверяется с закреплённой SHA-256 из метаданных официального релиза.
2. При импорте VLESS/Trojan-ссылок сохраняются `cs` (TLS-шифры), `pcs` (отпечатки сертификатов), `vcn` (имена проверки сертификата), `ech` (формат ECH Xray) и `pqv` (ML-DSA-проверка REALITY). Они сохраняются в профиле и повторно экспортируются в ссылку.
3. Профили VLESS/Trojan с этими TLS-параметрами используют встроенный Xray. Настройки передаются ядру без перевода в несовместимые параметры sing-box. Явно заданный fingerprint сохраняется; для `cs` без fingerprint применяется `unsafe`, как в 3x-ui. Название `unsafe` здесь относится к fingerprint, проверка сертификата этим не отключается.
4. Для пути через Xray добавлены WebSocket, gRPC и HTTPUpgrade; TCP и XHTTP сохранены. Псевдонимы `raw` и `splithttp` при импорте ссылок приводятся к TCP и XHTTP.
5. В REALITY-конфигурацию Xray передаются `password` и `mldsa65Verify`. При импорте V2Ray JSON принимается новое имя `password` с сохранением поддержки старого `publicKey`.
6. Удалённый в новом Xray параметр `allowInsecure` не игнорируется: для TLS-профиля, использующего Xray, выводится ошибка. Необходимо выключить пропуск проверки и настроить сертификат, `pcs` или `vcn`.
7. Проверка версии Xray выполняется также для профилей, которым приложение выбрало Xray автоматически.

8. Исправлен URL-тест для профилей Xray: запускается отдельный тестовый процесс с временной конфигурацией и свободным SOCKS-портом. Активное соединение не перезапускается. Проверяются как автоматически выбранный Xray для VLESS/Trojan, так и явный тип Xray. Добавлены тайм-аут, отмена и удаление временных файлов. Результат сохраняется до вызова очистки недоступных профилей подписки.

9. Исправлен обычный запуск Xray 26.10.31: он получает файл `extra.json`. Расширение `extra.conf` отвергается новым загрузчиком Xray даже при `-format json`. Для остальных внешних ядер прежнее имя файла сохранено. Ошибка запуска или ожидания SOCKS-порта возвращается в интерфейс до включения основного прокси/TUN; созданный процесс завершается. Ошибка запуска основного ядра также завершает Xray. Повторный ошибочный Start не сбрасывает уже работающее соединение.

10. Исправлены название NekoBox в заголовке, подсказке и свойствах EXE, а также версия файла Windows. Пользовательские названия сохраняются; старые стандартные NyameBox/Iblis заменяются на NekoBox.
11. Панель журналов уменьшается независимо от минимальных размеров скрытых вкладок. Разделитель видим, двойной щелчок делит панели поровну; «Сбросить расположение панелей» доступно по Ctrl+Shift+L. В компактной вкладке маршрутов есть прокрутка.
12. Сохраняются нормальные размеры окна и его состояние Qt. Исправлены нулевые/отрицательные координаты мониторов, возврат с отключённого монитора и учёт настроек сохранения геометрии.
13. История журнала ограничена 2000 строками без накопления пустых блоков. Большие пачки сообщений делятся перед отображением. Очистка удаляет и ожидающие строки. Контекстные меню и старые объекты подсветки освобождаются. Управление журналом переведено на русский.

## Сборка через GitHub

Подготовлен файл `.github/workflows/windows10-compat.yml`. Он собирает только Windows x64, использует выбранный коммит и не публикует релизы или пакеты.

Для запуска нужна собственная копия проекта (Fork) в GitHub с доступом на запись. В форке `dodon353/nekobox` изменения находятся в ветке `codex/windows10-compat-20261102`.

1. Создайте Fork исходного репозитория в своём GitHub.
2. Примените приложенный патч к указанному базовому коммиту в отдельной ветке с именем `codex/windows10-compat-20261102`.
3. Отправка этой ветки запускает проверку и сборку. Если GitHub отключил Actions в новой копии, включите их во вкладке Actions и повторите запуск.
4. После успешного завершения скачайте артефакт `NekoBox-Windows10-x64-experimental`. В нём должны быть ZIP с программой и установщик EXE.
5. Для первой проверки распакуйте ZIP в новую папку. Сохраните резервную копию текущих профилей и проверьте импорт своей подписки, подключение, затем TUN. Тестировать работу сети должен пользователь Windows.

Для подготовленного форка изменения можно загрузить через подключение GitHub без ручной работы с патчем, если этому подключению предоставлен доступ на запись.

## Ограничения

Это ограниченное обновление совместимости. Полная поддержка всех возможностей 3x-ui 3.11.0 и Xray 26.10.31 не заявляется. XDRIVE, finalmask/XDNS/Lua, новые серверные функции панели, сложные цепочки с несколькими внешними ядрами и все варианты JSON/YAML-подписок здесь не проверялись и не дорабатывались. Новые поля пока не имеют отдельных элементов редактора интерфейса: они поступают из ссылок и сохраняются в профиле.

Переключение некоторых профилей на Xray может влиять на цепочки и маршрутизацию. Для них нужна отдельная проверка. gRPC, WebSocket, HTTPUpgrade и Trojan принимаются проверенным Xray, но ядро выводит сообщения об устаревании этих вариантов.

python3 tests/xray-url-test/test_url_test.py --xray /absolute/path/to/xray
python3 tests/external-core-start/test_core_start.py --core /absolute/path/to/nekobox_core --xray /absolute/path/to/xray
python3 tests/streamsettings/test_ech_persistence.py --qt
python3 tests/test_link_tls.py
python3 tests/ech-share-links/test_ech_share_links.py
python3 tests/query-decoding/test_query_decoding.py
